## 一、核心问题

当前资讯中心解决了"信息入口"(聚合招标公告、评分排序),但停留在"推给你看"。
对投标企业,真正的价值是把**匹配的商机 → 可行动的投标决策**:
- 这个项目我该不该投?
- 我(企业)具备哪些资质、业绩、人员?
- 我的商务部分能不能得分?和对手比差距多大?
- 值得投入多少精力去配置标?

## 二、数据基础:企业知识库 / 资质库

投标决策的"底账",必须建两类资质库:

### 1. 企业资质库
- 营业执照、资质证书(施工总承包/专业承包/安全生产许可证等,含等级、有效期)
- 历史投标业绩(项目名称、规模、金额、业主、中标/未中标)
- 财务实力(近年营收、资产负债)
- 人员(注册建造师、安全员、工程师等个人资质)
- 获奖与信用(奖项、AAA 信用、社保缴纳)

### 2. 个人资质库
- 企业员工持有的注册类证书(一级/二级建造师、注册造价师、注册安全工程师……)
- 学历、职称、业绩经历

> 资质库来源:企业上传的证照扫描件 / 手动录入 / (未来)与证照库对接。
> 需设计资质字段模型与 OCR/解析入库能力。

## 二、分阶段决策管线(TODO 核心)

```
资讯(招标公告)
   │ 阶段1: 匹配(行业/地域/金额/关键词 规则 + 画像评分)
   ▼
备选库 (Candidate Pool)          —— 大量公告,粗筛
   │ 阶段2: 子agent1 初筛(结合资质库判断"能投吗")
   ▼
分析库 (Analysis Pool)           —— 初筛通过, 待深度分析
   │ 阶段3: 子agent2 异步深度分析(逐项目并行)
   ▼
投标库 (Tender Pool)             —— 进入正式投标评估
   │ 阶段4: 商务维度评分报告
   ▼
评分报告 (PDF/DOCX) + 决策建议   —— 附带投标项目评分报告
```

### 阶段 1:匹配 → 备选库
- 规则 + 评分:行业、地域、金额区间、关键词(复用现有 `BusinessValueScorer`)
- 与「公司画像」联动(用户已在设置页维护)
- 落入 `candidate_hotspots`(备选库),标记 `stage=candidate`

### 阶段 2:子 agent 初筛 → 分析库
- 目标:把"看起来相关"收敛为"企业有资格投"的
- 初筛规则:资质等级要求 vs 资质库、业绩要求、人员要求、保证金金额、投标资格条件
- 自动化能力:能解析招标文件的资格要求章节则自动判断,否则人审
- 落入 `analysis_pool`,标记 `stage=analysis`

### 阶段 3:异步分析(子 agent 2,逐项目并行)
- 对分析库每个项目异步任务:
  - 解析招标文件:资格要求、评分办法、合同条款、技术标准
  - 结合企业资质库,输出"企业能不能投、胜算几何、需要补齐什么"
- 分析结果结构化存储,前端可看每一项分析的进度与结论

### 阶段 4:投标评分报告(商务部分)
- 商务分维度(用户强调"商务部分比较重要"):
  - 投标项目经历(同类项目业绩数量/金额/相似度)
  - 资质证书覆盖度(资格项逐项勾对)
  - 个人资质(项目经理 + 项目管理班子配置)
  - 商务报价合理性(参考历史中标价,粗估区间)
  - 其他:资信状况、社保、信用记录
- 产出:投标项目评分报告(PDF/DOCX),附带整体结论、失分风险点、补强建议
- 报告归入项目文档,投标团队可直接基于报告撰写投标文件

## 四、与现有模块的关系

| 现有能力 | 在本构想中的角色 |
|---|---|
| 资讯中心 / HotspotItem | 商机入口,阶段 1 匹配的输入 |
| 公司画像(待实现 P1) | 阶段 1 匹配的个性化输入 |
| BusinessValueScorer | 阶段 1 评分基础(需补充资质维度) |
| Agent/Skill 引擎 | 阶段 2/3 的 agent 与子 agent 载体 |
| 标书生成(generate) | 阶段 4 报告产出后的下游(生成投标文件) |
| 项目中心 Project | 从投标库创建正式投标项目 |
