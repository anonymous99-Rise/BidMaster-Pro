# 知识库模块设计 — 资质库/知识库与智能投标决策链路

> 状态:设计稿 v2(2026-10-09,基于用户深化讨论 + 市面产品调研)
> 前置:09-smart-bidding-todo.md(构想总览);本文档是"知识库"模块的详细设计
> 定位:知识库是**与"招标工作流、资讯与管理"同级的顶级模块**,内含多个子模块,
> 是阶段 1~4(备选→初筛→分析→评分)的地基。

---

## 一、设计原则(来自用户输入与竞品共识)

1. **不是一个功能,是一个模块**:知识库与招标工作流/资讯/管理同级,下面挂子模块
2. **双库联动**(行业共识,智标AI/钛投标/元启智标均此架构):
   - **企业私有库**:用户维护的资质、业绩、人员、素材(准、可信)
   - **行业公开库**:子 agent 从公开渠道采集的工商、中标业绩、信用(全、自动)
   - 私有库为主,公开库做"预填 + 交叉校验",**人审后才入库**
3. **公开性问题的回答**:子 agent 采集公开信息是必要的,但定位是
   "减轻录入负担 + 发现遗漏",不是替代企业自己维护(敏感数据如财务、
   人员社保必须私有维护,不从公开渠道抓)
4. **评分权重不拍脑袋**:优先解析招标文件的真实评分细则,行业默认权重仅兜底

## 二、模块结构(前端导航)

```
智能招投标平台
├── 工作台 (Dashboard)
├── 招标工作流
│   ├── 标书解读 (Interpret)
│   ├── 标书生成 (Generate)
│   ├── 标书排版 (Format)
│   └── 标书检查 (Check)
├── 资讯中心 (News)
│   └── [阶段1] 备选库 ← 资讯匹配落库的展示位
├── ★ 知识库 (KnowledgeBase) —— 新顶级模块
│   ├── 企业资质 (公司基本信息 + 资质证书 + 财务 + 信用)
│   ├── 业绩库 (历史投标/中标项目, 支持公开信息预填)
│   ├── 人员资质 (人员档案 + 注册证书 + 个人业绩)
│   ├── 方案素材 (技术方案/施组/常用章节, RAG 向量化)
│   └── 公开信息采集 (子 agent 任务: 搜索-预填-人审)
├── 商机分析 [新]
│   ├── 分析库 [阶段3] (异步深度分析进行中/已完成)
│   └── 投标库 [阶段4] (评分报告 + 决策建议)
└── 系统 (Settings)
```

> 说明:「商机分析」可以并入资讯中心(备选库/分析库/投标库三页签),
> 待知识库落地后再定;知识库必须独立成模块。

## 三、数据模型(核心表)

```sql
-- 企业(多租户预留 company_id, 单企业部署可省)
company_profile     -- 已有(公司画像), 扩展: 统一社会信用代码/注册资本/成立日期

-- 资质证书
certificate (
  id, company_id, name,          -- 如"建筑装修装饰工程专业承包"
  level,                          -- 一级/二级/甲级...
  cert_no, issuer,                -- 证书编号、发证机关
  valid_from, valid_until,        -- 有效期(到期提醒!)
  scope,                          -- 承包范围
  file_id,                        -- 扫描件(MinIO)
  verify_status,                  -- pending/verified/expired
  source                          -- manual/ocr/public_agent
)

-- 业绩
achievement (
  id, company_id, project_name,
  owner_org, amount,              -- 业主、中标金额
  sign_date, completion_date,
  category,                       -- 工程类/货物类/服务类(与资讯 industry_code 对齐!)
  region,
  proof_file_id,                  -- 合同/验收证明扫描件
  source,                         -- manual/public_agent(ccgp中标公告解析)
  confidence                      -- 公开采集的置信度, 人审后置 verified
)

-- 人员
personnel (
  id, company_id, name, id_card_no_enc,
  title,                          -- 职称
  education, major,
  social_security_months,         -- 社保(商务分常查)
  resume_text
)
personnel_certificate (
  id, personnel_id, cert_type,    -- 一级建造师/造价工程师/安全B证...
  major, level, cert_no, valid_until, file_id
)

-- 方案素材(RAG)
material (
  id, company_id, category,       -- 施组/技术方案/安全预案/常用章节
  title, file_id, chunk_index     -- 入 chroma, 与项目资料隔离
)

-- 公开采集任务
intel_task (
  id, company_id, type,           -- bid_record(搜中标公告)/credit/qualification
  query, status,                  -- pending/running/done/failed
  result_json, reviewed           -- 人审状态
)

-- 商机阶段(阶段1~4)
hotspot_items.stage  -- 新增: null→candidate(备选)→analysis(分析)→tender(投标)
analysis_pool (      -- 阶段3: 每个项目一条分析任务
  id, hotspot_id, status,          -- queued/running/done/error
  eligibility_json,                -- 初筛逐项结果(阶段2产出)
  analysis_json,                   -- 深度分析结论
  score_report_file_id             -- 评分报告 docx/pdf
)
```

## 四、公开信息采集(PublicIntel 子 agent)——回答"公开性"

| 数据 | 公开渠道 | 采集方式 | 人审策略 |
|---|---|---|---|
| 中标业绩 | 中国政府采购网/各省交易平台(已接的源!)搜企业名 | 新增 `company_bid_search` 采集器:复用现有 fetcher,query=企业名,解析中标公告→项目名/金额/日期 | **逐条人审**后入业绩库 |
| 工商信息 | 国家企业信用信息公示系统 | 手动为主(反爬强),手动填+快照存档 | 手动确认 |
| 信用/处罚 | 信用中国 | 手动为主 | 手动确认 |
| 资质证书 | 部分省住建厅可查,覆盖不全 | 扫描件 OCR(一期)+ 手动 | OCR 结果人审 |

- 复用现有资讯采集基础设施(fetcher/skill/字段提取),增量小
- **业绩预填是杀手场景**:中标公告里项目名/金额/日期结构完整,自动解析+
  人审确认,业绩库从"纯手工"变"AI 预填 80% + 人审 20%"
- 合规:仅采集公开渠道,频率限制,记录来源 URL;不抓需登录/付费的数据

## 五、初筛机制(阶段 2)——回答"初筛怎么确定"

**双引擎,三态输出,人审兜底**:

```
分析库任务
   │
   ├─ 规则引擎(硬筛, 零成本, 先跑)
   │    输入: 招标文件解析出的资格条件清单(Interpret 已有解析能力)
   │    比对: 资质库逐项勾对(资质等级/注册资本/业绩数量年限/人员证书)
   │    输出: 每项 符合✓/不符✗/无法判定?
   │
   ├─ LLM 引擎(软筛, 只处理规则无法判定的项)
   │    输入: 模糊条款("具备类似项目经验")+ 资质库摘要
   │    输出: 判定 + 置信度 + 理由
   │
   └─ 汇总三态:
        全部✓        → 自动进阶段3(异步深度分析)
        任一✗        → 标记"资格不符"(保留, 可人工复核推翻)
        含?          → 进人审队列(前端待办)
```

- 人工参与点:默认"?"项必须人审;✗ 项可人工推翻;全自动只对全✓生效
- 废标红线(保证金/时限/形式要求)在阶段 3 深度分析里查,不在初筛

## 六、商务评分模型(阶段 4)——回答"权重维度"

**权重双轨**:
1. **解析招标文件评分细则**(优先):Interpret 引擎已能解析评分表,
   提取"评分因素-分值-标准"三元组 → 按真实权重算分,输出与评标办法对齐
2. **行业默认权重**(兜底,招标文件未细写时),来自行业实务调研:

| 维度 | 默认权重 | 评分依据(资质库数据) |
|---|---|---|
| 类似业绩 | 30% | 数量/合同金额/相似度(分类对齐)/近3年时效 |
| 资质证书 | 25% | 招标要求逐项勾对,等级/有效期 |
| 人员配置 | 20% | 项目经理证书专业等级、班子齐套、社保 |
| 财务状况 | 10% | 营收/净资产(近三年) |
| 信用与获奖 | 10% | AAA/奖项/无处罚记录 |
| 商务响应 | 5% | 偏差条款/保证金/文件齐套 |

> 行业参考:商务部分占总分通常 10%~20%(技术标为大头);
> 商务标内部业绩(25~35)/资质(15~25)/人员(20~30)/财务(10~15)/信用(10~15)。
> 政府采购注意财库〔2016〕205 号:资质业绩作加分项不作资格条件的合规线。

**产出**:投标项目评分报告(docx/pdf,复用 Format 管线):
结论(建议投/谨慎/放弃)+ 逐项得分与依据 + 失分风险点 + 补强建议
(如"缺 XX 证书,建议联合体/分包")。
